## 📄 MIT License Explained

### Why MIT (Not Apache 2.0)?

| Reason | Explanation |
|--------|-------------|
| **Academia-Friendly** | MIT is the standard for research code (PyTorch, papers with code) |
| **Maximum Adoption** | Simpler = fewer legal questions = more users/citations |
| **Low Patent Risk** | DL research rarely involves novel patents (Apache's patent clauses unnecessary) |
| **Portfolio Context** | You're showcasing **skills**, not building a startup |
| **Simplicity** | 1 file (LICENSE) vs 2 files (LICENSE + NOTICE) |

### MIT vs Apache 2.0 Comparison

| Aspect | MIT | Apache 2.0 | Winner |
|--------|-----|------------|--------|
| **Length** | 170 words | 2,800 words | ✅ MIT (simple) |
| **Patent Protection** | ❌ Silent | ✅ Explicit grant + retaliation | Apache (but low risk here) |
| **Trademark** | ❌ No protection | ✅ Protected | Apache (but branding less critical) |
| **Attribution** | License + copyright | License + copyright + NOTICE + changelog | ✅ MIT (less bureaucracy) |
| **Change Notices** | Optional | **Required** | ✅ MIT (easier for users) |
| **Academic Use** | ✅ **Standard** | Less common | ✅ MIT |
| **Corporate Use** | ✅ Accepted | ✅ **Preferred** | Tie (both good) |

**Verdict for This Repo:** MIT is the better choice.
