## 🆚 MIT vs. Apache 2.0 — Why We Chose MIT

| Aspect | MIT License | Apache 2.0 License | Our Choice |
|--------|-------------|-------------------|------------|
| **Length** | ~170 words (simple) | ~2,800 words (comprehensive) | ✅ **MIT** — Simplicity |
| **Patent Rights** | ❌ Silent on patents | ✅ Explicit patent grant + retaliation clause | MIT (low patent risk for academic DL) |
| **Trademark** | ❌ No protection | ✅ Explicitly protects project names | MIT (branding less critical) |
| **Attribution** | ✅ License + copyright notice | ✅ License + copyright + NOTICE file + change log | ✅ **MIT** — Less bureaucracy |
| **Change Notices** | Optional (courtesy) | ✅ **Required** — must document all changes | ✅ **MIT** — Easier for users |
| **Corporate Adoption** | ✅ Very high | ✅ **Extremely high** (preferred by legal teams) | Tie (both corporate-friendly) |
| **Academic Use** | ✅ **Standard** for research code | ✅ Less common in academia | ✅ **MIT** — Academic norm |
| **File Overhead** | 1 file (`LICENSE`) | 2 files (`LICENSE` + `NOTICE`) | ✅ **MIT** — Cleaner |

## 🎓 Why MIT is Ideal for This Repository

### 1. **Academia-Friendly**
- Most research code uses MIT (PyTorch, TensorFlow research modules, academic repos)
- Citation-based credit model (papers cite your code, not license enforcement)
- Low friction for reproducibility (researchers can easily adapt your code)

### 2. **Maximum Adoption**
- Simpler license = fewer legal questions = more users
- No NOTICE file requirements = easier to integrate
- Portfolio projects benefit from **reach > control**

### 3. **Patent Risk is Low**
- Deep learning research code rarely involves novel patents
- If someone patents your CNN architecture, citation > license protection
- Apache 2.0's patent clauses matter more for infrastructure (Kubernetes, Android)

### 4. **Simplicity for Portfolio**
- You're showcasing **skills**, not building a startup
- One file (`LICENSE`) vs. two files (`LICENSE` + `NOTICE`)
- Clear, short, universally understood

### 5. **Industry Compatibility**
- MIT is accepted **everywhere** (startups, Big Tech, academia, government)
- No compliance burden (no "you must document changes" requirement)

## 🔄 When Would Apache 2.0 Be Better?

**Consider Apache 2.0 if:**

1. **Commercialization Plans**
   - Planning to build a company around this code
   - Worried about patent trolls (Apache has defensive termination clause)

2. **Infrastructure/Platform Code**
   - Building a tool others will integrate deeply (frameworks, SDKs)
   - Want explicit trademark protection for brand names

3. **Corporate Downstream Users**
   - Enterprise legal teams **prefer** Apache 2.0 (clearer patent terms)
   - You want contribution agreements (Apache-style CLAs)

4. **Open Core Model**
   - Open-source version + commercial extensions
   - Need clear trademark separation

**For this portfolio:** None of the above apply → **MIT is the right choice.**
